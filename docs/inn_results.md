(the repo's headline number); Err_resim has an outlier guard that clamps each value at 10.

### 1.3 Known issues

| Row | Observation (from the logs and the JSON) |
|---|---|
| kinematics, INN (L2+MMD) | Err_resim has extreme outliers: mean 599,845 unclamped, 4.41 clamped, median 0.0119. The provisional re-simulation error during training was 1e5-1e6 from epoch 37 on, while the latent MMD term stayed at noise level (about -3e-4). Cause not verified. |
| ballistics, cINN | Median Err_resim 4.76e-05, but a few samples are far off (max 21.3), so the mean is 0.1226 unclamped / 0.1019 clamped. |
| ballistics, INN (ML) | Validation NLL was still falling at epoch 49 (-3.61) while the provisional re-simulation error rose from about 0.001 (epochs 3-4) to 0.021, and the mean z² on validation data ended at 2.76 (3 expected for a 3-dimensional N(0, I)). Consistent with the integer-v0 density spikes described in `docs/mdn.md`, not proven. |

### 1.4 Evaluation caveats

| Topic | Detail |
|---|---|
| Ground truth, kinematics | 2e9 proposals, 998/1000 y* complete, minimum 444 samples, 1462 s |
| Ground truth, ballistics | 5e7 proposals, 999/1000 y* complete, minimum 111 samples, 4702 s |
| Integer launch speed v0 (ballistics) | Not dequantized (`--dequantize-v0` off), as in the MDN, autoencoder and FMPE branches. Ballistics Err_post includes the integer-v0 penalty every continuous model pays (`docs/metrics.md`). |
| Paper comparability | Not stated in the paper: MMD estimator and kernel, training budget, optimizer. Table 2 (ballistics) averages are computed with clamped values, but the clamp value is not given; Table 1 does not say. Timings are on a GTX 1080 Ti, with no stated unit (per y* or per batch). So absolute values cannot be matched exactly, and the repo's own MDN also scores below the paper. |
| Inference time | CPU, 1000 samples per y*. Comparable only with other models run on the same device, not with the paper's GTX 1080 Ti numbers. |
| Seeds | One seed per row, so differences of a few percent are not meaningful. |

## 2. Architecture and design choices

Origin: **paper** = stated in the paper; **mine** = my choice, the paper is silent; **repo** = placeholder shared
by every model in this repo (MDN, autoencoder, FMPE).

### 2.1 Network (same for the three rows except the conditioning)

| Choice | Value | Origin | Why |
|---|---|---|---|
| Model family | RealNVP-style affine coupling flow | paper | "Ardizzone et al. 2019, based on RealNVP" |
| Coupling block | GLOW-style, both halves transformed per block with two subnets: `v1 = u1*exp(s2(u2,c)) + t2(u2,c)`, `v2 = u2*exp(s1(v1,c)) + t1(v1,c)` | mine | paper only says "affine coupling layers"; closed-form inverse, log-determinant is the sum of the scales |
| Blocks | 8 (= 16 coupling transformations) | mine | reasonable depth, not tuned |
| Subnet | MLP, 3 hidden layers, width 303, ReLU, linear output of size 2 x (other half) | mine (width derived) | width solved from the parameter budget |
| Parameter budget | about 3M trainable: INN 2,981,584; cINN 2,991,280 (kinematics), 2,986,432 (ballistics) | paper | "roughly the same number of parameters (~3M)" for all models |
| Activation | ReLU | mine | repo default (MDN); `--activation` also offers leaky_relu, silu, tanh, not compared |
| Scale clamp | `s = 2.0 * 0.636 * atan(s_raw)`, so each scale is in (0.14, 7.4) | mine | bounds `exp(s)` and `exp(-s)` so training and the inverse pass cannot blow up |
| Initialisation | last layer of every subnet zero, so the flow starts as the identity | mine | stable start |
| Mixing | fixed random permutation after every block except the last (seeded by `--seed`) | mine | every coordinate gets transformed by every other |
| Normalisation layers | none (no ActNorm, no BatchNorm) | mine | simplest working setup |
| Zero padding | none | paper | table: dim(z) = 2 on kinematics, 3 on ballistics, i.e. dim(x) - dim(y) |
| Input / output scaling | x and y standardised with training-set mean / std; sampling returns raw units | repo | same as the MDN and autoencoder |

### 2.2 The three rows

| | INN (ML) | INN (L2 + MMD) | cINN |
|---|---|---|---|
| Map | x -> [y_hat, z] | x -> [y_hat, z] | x -> z given y |
| dim y | kinematics 2, ballistics 1 | kinematics 2, ballistics 1 | kinematics 2, ballistics 1 (condition) |
| dim z (paper Tables 1-2) | kinematics 2, ballistics 3 | kinematics 2, ballistics 3 | 4 on both |
| Output | kinematics [y_hat (2), z (2)], ballistics [y_hat (1), z (3)] | same | z (4) |
| Conditioning | none | none | y concatenated to the input of every subnet, in both passes (paper) |
| Loss | Eq. (4): `1/2 (‖y_hat - y‖² / sigma² + ‖z‖²) - log abs(det J)` | Eq. (3): `w_y L2(y) + w_z MMD` | Eq. (5): `1/2 ‖z‖² - log abs(det J)` |
| Loss constants | sigma = 0.05 (standardised y units) | w_y = 1, w_z = 100 | none |
| MMD | n/a | batch of 1000 vs N(0, I), unbiased estimator, multi-scale IMQ kernel of `metrics/mmd.py` | n/a |
| Sampling | z ~ N(0, I), y_hat fixed to y*, x = f^-1([y*, z]) | same | z ~ N(0, I), x = f^-1(z; y*) |

| Detail | Choice |
|---|---|
| sigma, w_y, w_z | Placeholders. The paper only says "very low variance" for sigma and gives no weights. |
| Joint vs marginal MMD | Eq. (3) writes the MMD on z only. I use the joint MMD on `[y_hat, z]` vs `[y, eps]` (y_hat detached), the convention of the autoencoder branch. `--latent-mmd marginal` is the literal Eq. (3). |
| Eq. (4) | Paper: `1/2 (1/sigma² (y - y_gt)² + z²) - log abs(det J)`. The code implements exactly this (checked in `tests/test_inn.py`). The factor 1/2 on z² is what makes z follow N(0, I). |

### 2.3 Training protocol (repo placeholders, identical for all models)

| Setting | Value |
|---|---|
| Optimizer | Adam, learning rate 1e-3, weight decay 1e-5 |
| Schedule | cosine annealing per step to 0, gradient-norm clip 10 |
| Batch size / epochs | 1000 / 50 (50,000 steps) |
| Data | 1,000,000 training samples (seed 10000 + seed), 20,000 validation samples (seed 20000 + seed) |
| Seed | 0 |
| Hardware | training on the GPU (`cuda`, NVIDIA RTX 3060), scoring on CPU; torch 2.6.0+cu126 |
| Data generation (ballistics) | 160-190 s extra per run |

## 3. How these results were produced

```bash
EVAL=end bash experiments/sweep_inn.sh      # default mode: the six paper rows, train on cuda, score on cpu afterwards
```

which ran, for kinematics (`kin_`) and ballistics (`bal_`):

```bash
python experiments/train_inn.py --device cuda --run-name kin_inn_ml_s0    --problem kinematics --model inn  --loss ml    --seed 0
python experiments/train_inn.py --device cuda --run-name kin_inn_l2mmd_s0 --problem kinematics --model inn  --loss l2mmd --seed 0
python experiments/train_inn.py --device cuda --run-name kin_cinn_s0      --problem kinematics --model cinn              --seed 0
# the same three with --problem ballistics, run names bal_*
python experiments/evaluate_inn.py <run-name> --device cpu                # for each of the six
```

Outputs: `experiments/runs/<run>/{config.json,log.csv,summary.json,model.pt}` and
`metrics/results/<benchmark>_<run>.{json,npz}`. `kin_cinn_s0` was trained and scored in an earlier step with the
same commands.
